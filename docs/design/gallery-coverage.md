# Vega-Lite gallery coverage

Native (pure Emacs Lisp) rendering of the official Vega-Lite 6.4.1 gallery
against bin/chart's reference PNGs (`test/vl-examples/GROUP/ref/`).  Counts
are each group's `status.json` as regenerated by fc-qx1.48 on the
integrated engine (all eleven polish branches, 515bfd3 plus that bead's
fixes), with the image oracle run (rsvg-convert 2.62.4, Liberation Sans).

- pass: both backends render, the native SVG is within the example's
  differing-pixel threshold of the reference (default 0.03, canvas within
  8 px), and it lays out at three pixel and three cell sizes without overlap
- partial: it renders, but misses one of those (the reason is in `status.json`)
- unsupported: native compile refuses it (the reason names the feature)

Customization specs (`GROUP/custom/`, ours, eas-vl-gallery-custom.el) must
also check clean (every property they set is drawn) and match a text
golden.  Those without a bin/chart reference are **ref-pending**: their
image is not judged until bin/chart builds `custom/ref/NAME.png`, and they
are never counted as passing the image oracle.

written `note` in its `status.json` (fc-qx1.48): distributions

recorded ones for that reason.

## Polish: calculations (fc-qx1.43)

Every calculations example passes.  Two of bin/chart's references are
known to lack marks (Vega-Lite 6.4.1 drops bars under the theme's
`config.bar.cornerRadiusEnd`); their status.json entries carry
`refOmits`, so the oracle compares everything but those marks, at the
default 0.03, and the harness requires the native rendering to draw
them.  Legends placed in a plot corner (`orient: "top-left"`, ...) sit
in the plot on purpose and are not counted as overlaps.

- Customizability: `eas-spec-props.el` lists, per scope (mark type, axis,
  legend, scale, title, config blocks), the Vega-Lite properties eas
  draws; ERT re-measures the list (a property counts only if it changes
  the SVG).  `check` reports every other property as
  `UNSUPPORTED_FEATURE` with its path and `:property t`; the chart still
  draws natively without it.  `calculations/custom/` holds one
  customization spec per chart type (bar, line, area, point, rule, tick,
  text), checked clean, with text goldens; their bin/chart references
  are built by the harness where bin/chart is installed.
- Cost: `calculations/bench.json` (scripts/eas-gallery-bench.sh) has
  each example's bench-verb stages, byte-compiled, against the earlier
  build.  Layers now share their parent's transforms (run once per
  compile), zone-local time math uses a per-week cached offset instead
  of a zone lookup per row, and HCL stop colors are cached: the group's
  summed stage means went from 8.7 s to 3.6 s.

Second passes: area-circular (fc-qx1.42) keeps 13 of 13. Its
`bench.json` records the bench verb's numbers per example, before and
after. Its `custom/` specs, one per chart type (area, arc, radial),
set non-default properties throughout and must pass `check` with no
warnings. `check` names every property the renderer draws without as
an ignored `UNSUPPORTED_FEATURE` warning (`eas-spec-props.el`;
engine-spikes section 12).

## Integrated verification (fc-qx1.48)

The first test run of the integrated engine found 25 failing ERT tests
and 12 gallery regressions.  All were fixed in shared code; the notable
ones, by the hot spot they came from:

- Legends (three layouts): shared legends now flow into columns within
  the height left below the first plot, and the canvas grows to hold
  them; a size legend reads its re-ranged scale; a point mark's
  constant `shape` is its legend symbols' (Vega-Lite's defaultSymbolType);
  a view's own top/bottom legend with `titleOrient: "left"` uses the row
  layout that draws it; the orient-row layout honors `columnPadding`;
  discretizing legends keep their range labels under `legend.format`.
- Facet grid: a terminal facet fits every cell to one plot size, so the
  cells' axes share their rows; a band axis with fewer than three labels
  (which Vega never thins) gets room for them.
- Label fitting: a lone fitted view keeps the size it is fitted to and
  cuts (.43) or thins (.38) its labels; only composition cells grow the
  canvas instead (.45).  The gallery's collision check measures rotated
  labels in their rotated frame and at the axis's own `labelFontSize`.
- Projections: a projected view is no Vega-Lite "cell": no `config.view`
  fill or frame (both eas-geo's and eas-projection's).
- Lost hunks restored: the vega-datasets URL mirror, column-repeat grids,
  `mark.order`, the gallery bench's cold compile, title `font`/`fontStyle`
  and subtitle `font`/`fontStyle`, trail `fillOpacity`.
- Vega parity found on the way (checked against Vega-Lite 6.4.1 and Vega 6
  in node): band `paddingOuter` defaults to `paddingInner / 2` for ticks
  too; positional sqrt/pow scales are niced like linear ones; a cell's
  title wider than its plot widens the cell; a start-anchored chart
  title no longer over-widens the canvas.
- `eas-time-with-local-zone` (.44) was already wired into compile; dates
  in the gallery now match Vega's in the references' zone exactly.

Honored properties: the `eas-spec-props` audit now also probes binned
bars, ticks on continuous scales, a crowded nominal axis, a size legend
and a bottom legend, so `binSpacing`, `bandSize`, `labelOverlap`,
`symbolFillColor`, `columnPadding` and `titleOrient` count as drawn
where they are.  Two customization specs set legend properties nothing
draws (legend `padding`/`fillColor`/`strokeColor`/`cornerRadius` from
.41's unported legend style, legend `labelLimit`); those were removed
from the specs and stay reported by `check`.

## What is left

- Maps: topojson data and geoshape (12 examples).
- Legend frames (`padding`, `fillColor`, `strokeColor`, `cornerRadius`) and
  legend `labelLimit` are not drawn; `check` names them.
- In a terminal, a facet grid keeps each cell's own axis title, so narrow
  cells run those titles together (`multiview/custom/facet_grid_custom`
  at 60 columns); headers truncate to the cell width.
- 16 customization specs await bin/chart references (ref-pending).
- The rasterizer drift above: rebuilding the thresholds' baselines on the
  machine that builds the references would let those five return to 0.03.
